# Crash Hunter 2.0 (Antigravity Dual-Engine QA Skill)

Khi User/Sếp yêu cầu chạy "Crash Hunter", "Stress Test", hoặc kiểm thử săn lỗi Crash/RAM/Nav Leak trên dự án Android:

## 1. Khởi Động Nhanh (1-Touch CLI Runner)

Crash Hunter 2.0 đã được trang bị script hợp nhất `hunt.sh` tự động dò tìm cấu hình (Package ID, Thiết bị ADB, Độ phân giải màn hình, DeepLink, Maestro CLI) và thực thi kiểm thử:

```bash
# Chạy toàn bộ (Maestro Semantic UI + ADB Chaos Monkey) cho dự án hiện tại:
bash hunt.sh

# Hoặc chỉ định đường dẫn dự án Android và chế độ chạy:
bash hunt.sh -d /path/to/project -m all       # Chạy cả 2 Engines
bash hunt.sh -d /path/to/project -m maestro   # Chỉ chạy Maestro UI Flows
bash hunt.sh -d /path/to/project -m adb       # Chỉ chạy ADB Chaos Fuzzing
```

## 3. Triệu Hồi Subagent (`CrashHunterBot`) Khi Cần Chạy Ngầm

Để không làm gián đoạn luồng làm việc chính của Sếp, triệu hồi Subagent:
Dùng tool `define_subagent` với cấu hình sau:
- **Name:** `CrashHunterBot`
- **Description:** QA Automation Engineer.
- **System Prompt:**
  You are CrashHunterBot, a QA Automation Engineer. Run `./hunt.sh -d <target_project_dir>` (ensure `adb` is in PATH). Wait for it to finish.
  Then, analyze the logs in `logs/subagent/` and read `CRASH_REPORT_FINAL.md`. Apply these criteria:
  - **CRASH**: `FATAL EXCEPTION`, `OutOfMemoryError`, or `MediaCodec.*IllegalStateException` in `_filtered.txt`.
  - **NAV LEAK**: More than 2 identical Activities in `_backstack.txt`.
  - **RAM LEAK**: TOTAL PSS in `_mem_after.txt` is > 100MB higher than `_mem_before.txt`.
  - **DDOS / SPAM**: Many identical network requests in `_filtered.txt`.

  **IMPORTANT**: The app uses Timber, so logs often contain the exact file and line number (e.g., `(ViewModel.kt:150)`). You MUST extract this `(File:Line)` information and include it in your report! For example: `FAIL | Crash tại (SearchViewModel.kt:157)`.

  Read `CRASH_REPORT_FINAL.md` generated by the runner, verify findings, and report to parent agent.

## 4. Nghiệm Thu Kết Quả
Dùng `invoke_subagent` phái nó đi làm việc ở chế độ ngầm (`BypassSandbox=true`).
Khi Subagent báo cáo xong, tóm tắt các lỗi nghiêm trọng nhất cho Sếp kèm SỐ DÒNG CODE CHI TIẾT `(FileName.kt:LineNumber)`. Cảnh báo rủi ro về Coroutines/MVI State nếu có.
