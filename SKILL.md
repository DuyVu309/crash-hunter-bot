# Crash Hunter Bot (QA Automation Skill)

Khi User yêu cầu chạy "Crash Hunter" hoặc test crash (ADB, Monkey), bạn BẮT BUỘC thực hiện các bước sau:

## 1. Sinh kịch bản Test
Chạy lệnh python để tự động quét Package ID và DeepLink của dự án:
```bash
python3 .agents/skills/crash-hunter-bot/scripts/generate_tests.py
```
*(File sinh ra đã được tự động cấp quyền thực thi `chmod 0755`)*

### Bộ Kịch Bản Kiểm Thử Toàn Diện:
- `01_lifecycle.sh`: App Lifecycle & Screen Rotation Stress
- `02_monkey_stress.sh`: **Native ADB Monkey Crash Hunting (5000 random events, throttle 100ms)**
- `03_recording_service_stress.sh`: Foreground Service Stress (MediaCodec, Notification)
- `04_network_toggle_workmanager.sh`: Network Drop during Background AI Processing
- `05_folder_db_io_stress.sh`: Room Database Rapid Mutations
- `06_search_ime_stress.sh`: Search Input & IME Keyboard Stress (Unicode, Emoji, Backspace spam)
- `07_navigation_backstack_spam.sh`: Compose Navigation & Fast Backstack Pop (Anti-Activity Duplication)
- `08_audio_player_timeline_seek.sh`: Player Seekbar Dragging & High-Frequency State Isolation
- `09_bottom_sheet_modal_spam.sh`: Compose ModalBottomSheet & Dialog Stress
- `10_upload_worker_kill_restore.sh`: Upload Worker Kill & Data Recovery
- `11_tab_switch_fury.sh`: Multi-Tab Fast Switching
- `12_oom_large_note_stress.sh`: Long List Fling & PSS Memory Check (Lazy Layout stability)
- `13_paywall_back_race.sh`: Paywall Activity Navigation Race
- `14_locale_config_change.sh`: Theme & Font Scale Configuration Stress
- `15_full_chaos_monkey.sh`: Low Memory Killer (`am send-trim-memory RUNNING_CRITICAL`) + Chaos Monkey
- *(Tùy chọn)* `16_auto_deeplink_bom.sh`: Tự động kích hoạt nếu phát hiện intent-filter DeepLink.

## 2. Các Chế Độ Chạy

### Chế độ A: Chạy đơn lẻ 1 Case (Khuyến khích khi cần test nhanh Monkey hoặc Service)
Chạy trực tiếp case cần test qua terminal:
```bash
# Ví dụ: Chỉ chạy Native Monkey test
bash scripts/subagent/02_monkey_stress.sh
```
Kiểm tra kết quả tại `logs/subagent/<case_id>_filtered.txt`.

### Chế độ B: Triệu hồi Subagent (CrashHunterBot) chạy toàn bộ kịch bản
Dùng tool `define_subagent` với cấu hình sau:
- **Name:** `CrashHunterBot`
- **Description:** QA Automation Engineer.
- **System Prompt:** 
  You are CrashHunterBot, a QA Automation Engineer. Run `bash scripts/subagent/run_all.sh` (ensure `adb` is in PATH). Wait for it to finish.
  Then, analyze the logs in `logs/subagent/`. Apply these criteria:
  - **CRASH**: `FATAL EXCEPTION`, `OutOfMemoryError`, or `MediaCodec.*IllegalStateException` in `_filtered.txt`.
  - **NAV LEAK**: More than 2 identical Activities in `_backstack.txt`.
  - **RAM LEAK**: TOTAL PSS in `_mem_after.txt` is > 100MB higher than `_mem_before.txt`.
  - **DDOS / SPAM**: Many identical network requests in `_filtered.txt`.
  
  **IMPORTANT**: The app uses Timber, so logs often contain the exact file and line number (e.g., `(ViewModel.kt:150)`). You MUST extract this `(File:Line)` information and include it in your report! For example: `FAIL | Crash tại (SearchViewModel.kt:157)`.
  
  Read `CRASH_REPORT_FINAL.md` generated by the runner, verify findings, and report to parent agent.

## 3. Thực thi & Nghiệm thu
Dùng `invoke_subagent` phái nó đi làm việc ở chế độ ngầm (`BypassSandbox=true`). Quá trình chạy toàn bộ mất khoảng 15-20 phút.
Khi Subagent báo cáo xong, tóm tắt các lỗi nghiêm trọng nhất cho User kèm SỐ DÒNG CODE CHI TIẾT. Cảnh báo rủi ro về Coroutines/MVI State nếu có.
